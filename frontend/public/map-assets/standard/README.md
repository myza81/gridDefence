# Offline Standard basemap — Peninsular Malaysia

This folder holds the **offline Standard Engineering Map** package. It is served
by the app at application-relative paths under `/map-assets/standard/**`, so the
Standard map works with **no internet connection** and **no separate tile
server** (Vite dev serves `frontend/public/**`; any static server does in
production).

## What is committed vs generated/fetched

**Committed (small, text, auditable):**

| File | Purpose |
|---|---|
| `style.json` | MapLibre style referencing only local assets (generated by `frontend/scripts/build-standard-style.mjs` via `protomaps-themes-base`). Audited to contain **no external hosts**. |
| `manifest.json` | Declares the binary assets, coverage, zoom, source, licence, checksums. |
| `attribution.txt` | Required OSM/Protomaps/Noto attribution. |
| `README.md` | This file. |

**NOT committed (large binaries — git-ignored, fetched locally):**

| Path | Purpose |
|---|---|
| `peninsular-malaysia.pmtiles` | Single-file vector tile archive (PMTiles), read via HTTP range requests. |
| `glyphs/{fontstack}/{range}.pbf` | Glyph ranges for `Noto Sans Regular/Medium/Italic`. |
| `sprites/light.{json,png}` | Sprite set named `light`. |

Committing multi-hundred-MB binaries would bloat clone time and history, so the
binaries are excluded (see root `.gitignore`) and obtained per-workstation.

## Install the binaries (Windows, no Docker, no admin)

1. Open **PowerShell** in the repository root.
2. Activate the Python venv: `.\.venv\Scripts\Activate.ps1`
3. Fill in the `assets[*].url` (and ideally `sha256`) fields in `manifest.json`
   with your organisation's internal/licensed artifact URLs (see **Sources**).
4. Run: `python scripts/fetch_map_assets.py`
   - Downloads each asset, verifies its checksum (when provided), and unpacks
     glyphs/sprites into this folder. It refuses to overwrite without `--force`.
5. Point the frontend at the local style:
   `VITE_MAP_STYLE_STANDARD=/map-assets/standard/style.json` in `frontend/.env`.
6. `cd frontend && npm run dev`, then open `/substations?view=map`. Disconnect
   the network to confirm offline rendering.

If the binaries are absent, the app shows an honest "offline Standard map assets
are not installed" message and keeps the record list + Table view usable — it
never stalls.

## Sources (confirm licence/redistribution before hosting)

- **PMTiles archive:** a Protomaps regional extract of OpenStreetMap, or your
  own build (`pmtiles extract` from a global build over `bounds`). ODbL.
- **Glyphs + sprites:** `protomaps/basemaps-assets` (Noto Sans glyphs under
  OFL 1.1; `light` sprite).

`scripts/fetch_map_assets.py` does not hard-code any public URL — you supply the
source in `manifest.json` so no provider is assumed and nothing unlicensed is
fetched automatically.

## Regenerate `style.json`

```
cd frontend
npm run map:build-style     # writes public/map-assets/standard/style.json
npm run map:audit-style     # fails if it references any external host
```

## Range-request requirement

PMTiles reads the archive with HTTP `Range` requests. Vite dev and most static
servers honour this. For IIS/Nginx production hosting, ensure byte-range
serving is enabled for `.pmtiles` (see `docs/architecture/engineering-map.md`).
